# Design system and app chrome

Bring the Figma design into code: theme tokens, the icon set, the shared primitives and the top bar every page hangs off.

Design: `docs/design/pages-theme-and-content.md` and the Figma file `hKLgwCJbAN882A9dLlQKS0`.

Done when:

- [x] Status and code-surface tokens exist in `globals.css` for both modes.
- [x] Icons ship in the repo, not as a runtime dependency, and take `currentColor`.
- [x] `lint`, `typecheck`, `build` pass.

Built:

- `app/globals.css`: added `--status-success`, `--status-warning`, `--code-surface`, `--code-foreground`, `--code-muted` in light and dark, and exposed them through `@theme inline`.
- Fixed a real bug: `--font-sans` was set in `layout.tsx` but never mapped in `@theme inline`, so `font-sans` fell back to Tailwind's default stack instead of Geist. Doc prose was rendering in the wrong face.
- `components/icons.tsx`: 35 reicon outline icons inlined as React components, generated by `scripts/build-icons.ts`. Re-run that script to add more.
- `components/ui/`: `status-badge`, `field`, `callout`, `code-block`, `page-header` (plus `Kbd`). Button sizes moved to the 36px / 14px / 16px-icon scale from the spec, and `destructive` is now a solid fill.
- `components/chrome/`: `top-bar` (reader and admin variants), `theme-toggle`, `sign-out-button`.
- `app/admin/layout.tsx` now renders the top bar and the destructive error banner.

Note: the design spec says Remix icons and `@remixicon/react` is still in `package.json`. The reicon set replaced it in the UI. Drop the dependency once nothing imports it.
